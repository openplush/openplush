# Dependency graph

<!-- index: an interactive map of what depends on what, from subsystems down to single files, rebuilt with the site. -->

The [dependency graph](../depgraph/index.html) shows how the repository's parts depend on each other, read from the committed code each time this site is built, so it always matches the commit the site was built from. How the page is generated, and what the build checks, is in [Checks](checks.md#generated-dependency-graph-docs).

## Entries

- **Levels**, switched with the buttons or the keys `1`, `2` and `3`:
  - **System**: one node per category below, sized by file count. Only the major links are drawn; the hint under the graph says how many file-level edges make a link major.
  - **Modules**: the most important packages (each Cargo crate, the npm package, and each second-level folder elsewhere), as many as the hint under the graph says, ranked by (dependents × 3) + (lines / 100) and grouped by their top-level folder. Double-clicking a category on the System level shows all of its packages instead.
  - **Full graph**: every file, plus each external package. Double-clicking a package on the Modules level shows its files and their direct neighbours.
- **Categories**, which the sidebar filters by:
  - Frontend: `apps/` and `packages/`.
  - Backend: `bindings/`, the command-line tool and the WebAssembly worker.
  - Core: `crates/`, without the test kit.
  - Database: none; the repository has no database, so the node is drawn empty.
  - Tests: test files and test modules, `openplush-testkit`, `scripts/tests/` and the [fixtures](glossary.md).
  - Tools: `scripts/`, `.github/`, `.claude/` and `.specify/`.
  - Research: `research/`.
  - Docs: `docs/` and `specs/`.
  - External: packages from crates.io, npm and PyPI.
- **Edge kinds**, shown beside each dependency in the details panel:
  - `use`: a Rust `use` or qualified path to a module of this or another crate.
  - `mod`: a Rust `mod` declaration, from the parent module to the child.
  - `test`: a `mod` or `use` inside an inline `#[cfg(test)]` module.
  - `dev`: a use of a Cargo dev-dependency.
  - `import`: a TypeScript import, or a Python import of a local file or of a package the nearest `requirements.txt` declares.
  - `codegen`: a TypeScript type generated by ts-rs, pointing at the Rust type it is generated from.
  - `manifest`: a dependency a manifest declares that no source file names.
  - `ref`: a script, crate or package path named in a script, workflow, doc or agent file.
  - `data`: a fixture folder named in code.
- **Dependency depth**, one of the colour choices: the longest chain of production imports (`use`, `import`, `codegen`, `manifest`) below a file. Files that import each other share one depth.
- **Limits**:
  - A crate's re-exports make its `lib.rs` look more central than the files that hold the code, because a `use` of a re-exported item stops at `lib.rs`.
  - A `ref` edge is a text match, so a doc that mentions a script without using it still links to it.
  - Python standard-library imports are left out.
- **Keys**: `/` searches (Enter jumps to the first match), `R` resets the zoom, filters and search, `Esc` closes the details panel.
