## Pipeline Architecture

```
bytes ─▶ import ─▶ TriangleSoup ─▶ validate ─▶ ValidationReport
                                     │
                         RepairPlan ─▶ repair ─▶ ManifoldMesh + RepairReport
                                                    │
                              SeamSet (user) ─▶ chart ─▶ Vec<ChartMesh> + SewingMap
                                                    │      (cut-graph completion proposals)
                                   FlattenOptions ─▶ flatten ─▶ Parameterization + Metrics
                                                    │
                     Fabric + DirectionField ─▶ orient ─▶ grain angle per chart
                                                    │
                       Scale + PatternOptions ─▶ pattern ─▶ Vec<PatternPiece>
                                                    │
                                 LayoutOptions ─▶ layout ─▶ Vec<Sheet>
                                                    │
                                                 export ─▶ SVG / PDF bytes
```

- **Functional core**: each stage is a pure function of its inputs. `openplush-pipeline` memoizes by content hash, so a seam edit re-runs `chart` → `flatten` only for charts whose face set or boundary changed (FR-014).
- **Scale is late**: flattening is scale-equivariant; resizing re-runs only `pattern` onward.
- **Sessions for long stages**: `FlattenSession::step() -> Progress` lets the worker yield between iterations for progress and cancellation (single-threaded WASM).

### Warnings vs. errors (D-016, D-017)

Two distinct channels, never conflated:

| | Error | Warning |
|---|---|---|
| Means | A declared invariant is violated (Constitution III) | The geometry is valid but the result may sew badly |
| Examples | Chart is not a disk; det J ≤ 0; seam parity outside max(1.0 mm, 0.5%); allowance offset self-intersects unresolvably | Unsupported concavity (FR-025); low nap coherence (FR-052); piece smaller than 3× pile length (FR-055); stretch mismatch across a seam (FR-058) |
| Type | `Err(EngineError)` — the stage does not produce output | `Ok(output)` carrying a `WarningSet` |
| Effect on export | **Blocks** | **Never blocks** — acknowledged once, then unresolved entries print on the pattern's first page (FR-064) |

- `WarningSet` accumulates across stages and travels with the pipeline output. Each `Warning` carries a stable code, a located target (face/edge/piece ID), a plain-language explanation, and a `Remedy` (FR-065).
- `Remedy` is either `Actionable { proposal }` — an engine-computed change the UI offers preview-then-accept (extra seam FR-013, dart FR-022, piece split FR-052) — or `Advisory { what_to_change }`, naming a material or sizing choice the engine will not perform (FR-055, FR-058). A `Warning` with neither is a compile-time impossibility, which is how FR-065 is enforced rather than reviewed.
- Warnings are deterministic and ordered like everything else (Constitution V): sorted by code then by target ID, so the first-page summary is byte-stable.

### Worker boundary
- Mesh and intermediate state stay resident in the worker; the UI holds opaque handles.
- Control messages: small JSON (typed from `contracts/worker-protocol.md`; TS types generated from Rust).
- Geometry for rendering: transferable `Float32Array` / `Uint32Array` buffers (zero-copy transfer).
- Errors cross as typed `EngineError` codes with locations (face/edge IDs) the UI can highlight.

| 2026-10-17 | D-036 | **Repair step 2 stitches slivers instead of leaving cracks, and keeps both layers of a double-sided sheet.** Dropping a zero-area face alone opens a crack, and since `fillHoles` is opt-in that crack would become a sewn-open slit. A needle whose short edge is within the weld distance has already been collapsed onto its smaller vertex ID by the weld (step 1), so it arrives as a repeated-index face; a repeated-index face is dropped, which leaves no crack because its edges pair only with each other. Every remaining zero-area face (area within `ε_area`, data-model §11, as validation judges it) is a cap: its middle vertex, the one opposite its longest edge, lies on that edge within that tolerance. Caps are not split; each only records that its middle vertex lies on its longest edge. An edge of a face that is not a cap gets every vertex the caps put on it, following chains (a cap whose longest edge is part of that edge adds its vertex too), in order along the edge. Each such face is re-triangulated once with those vertices on its edges: no vertex is added or moved, and no triangle has three vertices on one of the face's edges, which is read off which edge each vertex lies on rather than recomputed with a tolerance. Then every cap is dropped. Faces on both sides of an edge get the same vertices on it, so no crack opens; a cap with no face across its longest edge is just dropped. The step is one pass and never fails itself. Within a few weld distances of a face's corner, a vertex can land on two of the face's edges, or a re-triangulated face can be zero-area; the half-edge build refuses either with its typed error naming the face, so the result is never silently wrong. Splitting caps and re-checking instead needs a number of rounds that grows about cubically with stacked caps (found in review, 2026-10-17). Of same-orientation duplicates the lowest face ID is kept. Opposite-orientation duplicates are both kept and flagged as a double-sided sheet, which sews as two pieces joined round its rim. A one-triangle sheet already closes into a shell; in a larger sheet every interior edge has four faces, two per layer, so step 3 must pair each face there with its own layer's neighbour (the flag says which faces are layers) and the layers meet only along the rim. Step 5 leaves a sheet's winding as it is: its layers already agree across the rim, and its signed volume is zero, so the volume rule cannot choose a side. Pairing by dihedral angle alone cannot tell the layers apart: they are coincident, and a cross-layer pair is orientation-compatible too. Every dropped and split face, and every sheet, is listed in `RepairReport` (Constitution VII). Validation judges topology as repair sees it, so it keeps both layers too (T180) | Accepted — maintainer, 2026-10-17 |

### Trade-offs accepted
- Smaller engine contributor pool (Rust) in exchange for zero-install distribution and one engine everywhere.
- No free seam-marking UI from Blender; we build seam drawing in Three.js.
- Single-threaded WASM in MVP; the performance budget must be met on the repaired mesh, since there is no remeshed proxy (D-024).
- No Spec Kit agent-context extension: `AGENTS.md` doesn't auto-list the current plan path; `.specify/feature.json` covers that.
