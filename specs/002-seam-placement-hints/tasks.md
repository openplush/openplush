## Format: `[ID] [P?] [Story] Description`

- **[P]** — can run in parallel (different files, no dependency)
- **[Story]** — which user story it serves
- `needs:ID[,ID]` — unticked tasks this one waits on, where the phase order alone does not say so
- `blocked:D-0NN` — a proposed decision this one waits on; only the maintainer clears it
- `human:XX` — needs a person (outside review, measured values); no agent picks it up
- Task IDs are `T0NN` and decisions `D-0NN`, as in every feature ([ADR 0021](../../docs/adr/0021-one-id-scheme.md)); an ID from another feature names it, as in `001 T084`.

|---|---|
| **T012** monotonicity property test | The single most important test in the feature. If it lands bundled, nobody checks whether it actually holds — and FR-006's guarantee becomes a comment |

## Phase 2: Foundational — signals and the threshold contract

**Purpose**: The signal/threshold split (D-002) is what makes monotonicity structural and SC-003's 1-second re-filter achievable. Every detector depends on it, so it lands first.

### Tests first

- [ ] T012 [P] `crates/openplush-hints/tests/monotonicity.rs` — `proptest` over random sensitivity pairs: the hint set at the lower sensitivity is a **subset** of the set at the higher one, for every category. **The single most important test in this feature.** Without it, FR-006's guarantee is a comment in a file
- [ ] T013 [P] `crates/openplush-hints/tests/determinism.rs` — identical input gives a byte-identical `HintReport`, and ordering is independent of insertion order (SC-008)
- [ ] T014 [P] `crates/openplush-hints/tests/scale.rs` — the same model at 80 mm and 600 mm produces different hint sets, because the length and radius thresholds are physical (FR-007). A test that passes when they are identical would be a test that permits FR-007 to go unimplemented

### Implementation

- [ ] T015 `crates/openplush-hints/src/signals.rs` — `HintSignals`: signed dihedral per edge, angle defect per vertex, integrated curvature over a geodesic disk of physical radius, symmetry candidates. Cached by mesh content hash
- [ ] T016 `crates/openplush-hints/src/sensitivity.rs` — sensitivity to threshold mapping, monotonically decreasing, **fixed absolute thresholds only** (D-003). A doc comment must state why percentile thresholds are forbidden, so the next person does not helpfully add them
- [ ] T017 `crates/openplush-hints/src/lib.rs` — `detect(&ManifoldMesh, Scale, &HintOptions) -> StageResult<HintReport>`. Takes `&ManifoldMesh` with no mutable path, so FR-010 is enforced by the borrow checker

**Checkpoint**: signals compute and filter monotonically. Detectors can now be added one at a time.

## Phase 3: US1 — See where seams belong (Priority: P1) 🎯 MVP

**Goal**: Instead of a blank surface, the maker sees the model's natural seam lines, listed by category, each explaining itself.

**Independent Test**: On the quadruped fixture, each category produces hints along the muzzle fold, neck crease, and head dome; a smooth sphere produces zero crease hints at default sensitivity.

### Tests for US1

- [ ] T018 [P] [US1] `crates/openplush-hints/tests/oracles.rs` — smooth sphere yields **zero** sharp-edge and concave-crease hints at default sensitivity (SC-004), and the categories appear in `absent` rather than simply being empty
- [ ] T019 [P] [US1] `crates/openplush-hints/tests/oracles.rs` — a cube yields exactly 12 sharp-edge chains, no more and no fewer. Catches both over-detection and chain fragmentation in one assertion
- [ ] T020 [P] [US1] `crates/openplush-hints/tests/concave.rs` — on the quadruped, concave hints appear at the neck and between the legs, and the convex muzzle ridge is **not** classified as concave. Sign errors are the obvious bug here and are invisible without this test
- [ ] T021 [P] [US1] `crates/openplush-hints/tests/dart.rs` — dart candidates cluster at the head dome and nose tip; a cylinder (developable) yields none
- [ ] T022 [P] [US1] `crates/openplush-hints/tests/symmetry.rs` — plane found on the quadruped with a low score; **none reported** on `asymmetric.glb`; score reported on `near-symmetric.glb` (SC-005)
- [ ] T023 [P] [US1] `crates/openplush-hints/tests/flood.rs` — the faceted fixture reports its over-cap categories in `flooded` and does **not** silently truncate the list (SC-010)

### Detectors

- [ ] T026 [US1] `crates/openplush-hints/src/crease.rs` — signed dihedral thresholding, with separate thresholds for convex and concave and the **concave threshold lower** (research R1: a shallow valley still vanishes when stuffed)
- [ ] T027 [US1] `crates/openplush-hints/src/chain.rs` — chain crease edges into polylines, preferring the smallest turning angle, ties broken by lowest provenance key. Stop at junctions and emit junctions as their own short hints rather than resolving a T-junction arbitrarily. **Chain once at the most permissive threshold, then filter by length** — re-chaining per sensitivity breaks monotonicity (data-model section 3)
- [ ] T028 [US1] `crates/openplush-hints/src/crease.rs` — **share the concave signal with 001's FR-025 unsupported-concavity warning** (D-004). One implementation, not two thresholds that drift. A tool that shows no hint and then warns about the same region reads as broken and erodes trust in both halves
- [ ] T029 [US1] `crates/openplush-hints/src/dart.rs` — integrated absolute Gaussian curvature over a physical-radius geodesic disk, clustered, one hint per cluster located at the peak vertex. Cluster once at the most permissive threshold, same reason as T027
- [ ] T030 [US1] `crates/openplush-hints/src/symmetry.rs` — area-weighted PCA candidates, reflection-ICP refinement, match score relative to bbox diagonal. **Report none when no candidate scores well, or when a second distinct candidate (normals more than 10° apart) also scores within the acceptance threshold** (D-006, D-010). Fixed iteration count and candidate ordering, no randomness
- [ ] T031 [US1] `crates/openplush-hints/src/explain.rs` — write the static `why` and `effect` text for all four categories, and the `detail` formatter. **This text is the teaching payload of the entire feature** and deserves more care than the code around it; it must say what a seam there *would do*, never that the maker *should* cut there
- [ ] T032 [US1] `crates/openplush-hints/src/suppress.rs` — suppress hints on detail parts (001 FR-005) and hints overlapping an existing seam within tolerance. A hint telling the maker to do what they already did is noise that makes the whole panel ignorable

## Phase 4: US2 — Turn a hint into a seam (Priority: P1)

**Goal**: Accept a hint in one action, see the flat-pattern effect, keep or discard. Nothing applies itself.

**Independent Test**: Every hint on the capsule and quadruped fixtures accepts into a valid seam or dart, editable afterwards like a hand-drawn one, with a preview first.

### Tests for US2

- [ ] T042 [P] [US2] `crates/openplush-hints/tests/accept.rs` — accepting any hint on any fixture yields a valid seam or dart: never a malformed or self-crossing path (SC-006)
- [ ] T043 [P] [US2] `crates/openplush-hints/tests/accept.rs` — an accepted hint becomes an **ordinary seam**, indistinguishable from a hand-drawn one in the resulting `SeamSet`. FR-030's real requirement, and the thing that keeps later editing uniform
- [ ] T044 [P] [US2] `crates/openplush-hints/tests/accept.rs` — declining a preview leaves the model byte-identical (FR-031); taking no action changes nothing (FR-032)
- [ ] T045 [P] [US2] `crates/openplush-hints/tests/unsewable.rs` — a hint whose acceptance would produce a sub-minimum piece warns first and still permits acceptance; one that would stop a chart being a disk is refused with proposals attached (FR-036, data-model section 6)
- [ ] T046 [P] [US2] `apps/web/tests/hints-accept.spec.ts` — Playwright: accept shows a flat-pattern preview, undo restores the hint to its un-acted state

### Implementation

- [ ] T047 [US2] `crates/openplush-hints/src/accept.rs` — `to_proposal()` converting a hint into 001's existing `Proposal`. Reuse, not a parallel mechanism: preview-then-accept, undo, and "nothing changes until confirmed" all come from 001 (Constitution VII)
- [ ] T048 [US2] `crates/openplush-hints/src/accept.rs` — line hints become a seam along the **whole chain**, not a starting point (FR-030). Region hints become a dart request, with direction and size chosen by 001's dart machinery from the cluster peak — this detector locates a dart, it does not design one
- [ ] T049 [US2] `crates/openplush-hints/src/accept.rs` — pre-acceptance sewability check against 001's validation: minimum piece size, pile multiple (001 FR-055), dart tightness, chart-is-a-disk. First three warn, the last refuses (FR-036)
- [ ] T050 [US2] `apps/web/src/hints/accept.tsx` — accept action, flat-pattern preview, keep or discard. **Symmetry has no accept button** — it gets a "use for mirroring" toggle instead, because it is a hint the maker uses rather than applies (data-model section 6)
- [ ] T051 [US2] `apps/web/src/hints/undo.ts` — accept, decline, and dismiss are all undoable through 001's existing undo stack (FR-035)

**Checkpoint**: US1 and US2 together are the feature's core loop. A maker can see a suggestion, understand it, try it, and keep it.
