# Fixtures

Test models and reference data. Licenses for every file are in [`LICENSES.md`](LICENSES.md).

| Directory | Holds | Used by |
|---|---|---|
| `meshes/` | Clean, closed, outward-wound triangle meshes in millimetres: capsule, cube, sphere as OBJ; `near-symmetric.glb` and `asymmetric.glb` for symmetry detection, `faceted.glb` for the hint flood, `quadruped.glb` as the seam-hint tuning model. `meshes/source-seams/` holds models whose UV cuts are their seam layout, as glTF and OBJ twins | Pipeline tests and the web app's end-to-end smoke test; source seam import |
| `defects/` | Exactly one model per repair defect class, each with only that defect | The defect-detection corpus: every file here must be detected and reported |
| `seams/` | Reference seam sets (JSON) for the models in `meshes/`, so pattern tests need no UI. Every chart they leave is a disk, except under `seams/non-disk/`, whose sets deliberately leave a chart that is not | Seam, chart, and pattern tests |
| `fabrics/` | Fabric profiles in the project schema's `fabric` shape, written by hand for tests and the quickstart. Their values are plausible, not measured: they are not presets (001 T084) | The CLI's `pattern` tests |

`meshes/`, `defects/`, and `seams/` are generated by [`research/fixtures_gen/`](../research/fixtures_gen/README.md). Do not edit them by hand: change the generator, run `python3 generate.py` there, and commit both. Its tests fail if the committed files and the generator disagree. The README there documents what each defect fixture contains.

Contributed models (CC0 or CC-BY only) go in `meshes/` with an entry in `LICENSES.md`.

## Seam-set format

```json
{
  "format": "openplush-seam-set",
  "version": 1,
  "mesh": "meshes/cube.obj",
  "vertexIndexBase": 0,
  "note": "what the cut is",
  "seams": [{"edge": [0, 1], "kind": "cut"}]
}
```

`mesh` is relative to `fixtures/`. An edge is a pair of **OBJ vertex indices** (the order of `v` lines), counted from `vertexIndexBase`, 0 or 1; every fixture here is 0-based. The smaller index comes first, and the list is sorted. This names an edge without depending on the engine's half-edge numbering. `version`, `vertexIndexBase`, and edge indices are JSON integers: `1.0` or `false` is invalid. `kind` is `cut` or `fabricBoundary`. The project schema's other seam kinds, `dart`, `opening` and `mandatory`, are refused for now. Every chart left by the cut is a topological disk, except for sets under `seams/non-disk/`.

## Dead-end format

```json
{"format": "openplush-dead-ends", "version": 1, "mesh": "meshes/source-seams/dead-end.obj", "vertexIndexBase": 0, "note": "…", "tips": [55, 66]}
```

`tips` are the 0-based OBJ vertex indices, ascending, where a UV cut stops inside the surface: a vertex on exactly one edge of the graph over UV cuts and material boundaries, and not on the surface boundary.
