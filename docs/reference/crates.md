# Crates

What each engine crate contains **today**, and what it actually depends on. Which crate *should* own a new piece of code is a rule, kept in [`crates/AGENTS.md`](../../crates/AGENTS.md#where-code-goes); the allowed dependency graph is in the [plan](../../specs/001-pattern-pipeline/plan.md#crate-dependency-dag-enforced) and enforced by `scripts/check-boundary.sh`. Signatures and item docs: `cargo doc --workspace --no-deps --open`.

## Built

|---|---|---|
| `openplush-geom` | `DVec2`, `DVec3`; exact predicates `orient2d`, `orient3d`, `incircle` returning `Sign`; `epsilon` (`ModelTolerances`, `SeamParity`, the constants behind them, and `UV_CUT`, the absolute UV-unit threshold above which two corner UVs make a cut); `units` (`Mm`, `Scale`); `GeomError` | `robust`, `thiserror` |
| `openplush-mesh` | `TriangleSoup` and `SourceCorner`; `SourceMaterials` (`names`, `by_primitive`, `material(primitive)`) and `MaterialIndex`, which a soup carries with `extra_uv_sets` (UV sets the file has beyond the one read): `TriangleSoup::new` gives an empty table, `with_materials(materials, extra_uv_sets)` sets them, and repair moves both unchanged onto the mesh; the half-edge `ManifoldMesh` (read-only accessors including `materials` and `extra_uv_sets`, `outgoing` returning `Outgoing`, `boundary_loops`, `debug_validate`; no public constructor); IDs `VertexId`, `EdgeId`, `HalfEdgeId`, `FaceId`, `ComponentId`, `MeshElement`, and `id_newtype!`, which defines a `u32` ID with `new`, `index` and the shared derives; `MeshError` with `CornerArray`, `Counted` and `MaterialFault`, where `InvalidMaterial` names the lowest primitive that a triangle uses but the table lacks (`Missing`), or whose material is not below the name count (`OutOfRange`); `validate(&TriangleSoup) -> ValidationReport`, which never fails and changes nothing. It welds used vertices within the weld distance (transitively, comparing only vertices in neighbouring weld-distance cells) and leaves out repeated-index faces and later copies wound the same way, keeping both layers of a double-sided sheet, then judges topology on what remains, as repair will see it; a vertex there is named by its weld group's smallest ID. The report lists, each sorted: `unwelded` groups; `zero_area` faces (area at or below the area tolerance, from the soup's own positions); `repeated_index` faces; `duplicates` (`Duplicate`: the copy, the first face it repeats wound its way or, for `DuplicateOrientation::Opposite`, the other way, and `Same` or `Opposite`); `non_manifold_edges` (`NonManifoldEdge`: ends and every face); `non_manifold_vertices` (faces split into more than one fan joined through shared edges); `winding_conflicts` (two-face edges both faces walk the same way); `non_orientable` (two-face edges where the flips a breadth-first walk assigns contradict); `inside_out` (shells, faces joined across two-face edges, that are closed and have non-positive signed volume, so an inside-out shell touching the rest only at a vertex or a non-manifold edge is still caught; a shell made only of a double-sided sheet's layers is closed and flat but not listed, since repair leaves its winding as it is); `boundary_loops` (one-face edges chained in their faces' direction, split wherever a vertex repeats, each from its smallest vertex); and `components` (vertex-connected, by faces; more than one is a defect). A soup with no triangles or an extent tolerances refuse is `Unmeasurable` (`NoTriangles`, `Extent { diagonal }`) with nothing else judged. `self_intersections` lists face pairs sharing no edge that cross along a segment longer than the weld distance, so a fold between faces sharing a vertex counts; faces that only touch (at a corner or edge-on), lie within the weld distance of one plane, or have no area are not listed, so shells overlapping only through coplanar faces go unreported. Candidates come from a bounding-box tree; the test is in floating point against the weld distance, since the report only warns. A vertex of valence k costs about k² pair tests. `RepairPlan` (five step toggles, all on by default, and `fill_holes`, the loops to fill, which are named by `LoopRef`, the lowest `SourceCorner` among the loop's vertices; a loop not listed stays an opening) and `RepairReport`, read through accessors that list each step's changes: welded groups, dropped repeated-index and duplicate faces (`DroppedCopy`), sheets, stitched caps and re-triangulated faces, paired edges (`PairedEdge`), added vertex copies (`VertexCopy`), flipped faces, orientation conflicts, components (`Component`), holes (`HoleReport`) and mandatory seams. Removals, flips and pairings name IDs of the soup given to repair, additions those of the repaired mesh. `into_manifold(&soup, &plan)` returns `(ManifoldMesh, RepairReport)` and is the only way to get a mesh: weld, drop repeated-index faces and copies and stitch caps, pair the faces on over-shared edges, split vertices (pairing-aware), pair again, orient, split components, compact unused vertices, then build. A step the plan turns off is skipped and what it would have fixed reaches the build, which refuses it with its typed error. Errors beyond the build's: `NoTriangles`, `UnusableExtent`, `UnknownHoleLoop` and `HoleFillUnavailable` (a `fill_holes` entry; filling is not built). A non-orientable conflict edge is refused as `InconsistentOrientation`, not cut, so `orientation_conflicts` stays empty. Report faces are the input soup's IDs, except that vertex copies, conflicts, mandatory seams and hole loops use the mesh's vertex IDs. | `openplush-geom`, `thiserror` |
| `openplush-seams` | `Proposal` (built only by `Proposal::new`), `ProposalId`, `ProposalKind`, `SeamReason`; `SeamKind`, `ChartFailure`; IDs `ChartId`, `SeamChainId`; `SeamSet` (`new`, `get`, `insert`, `remove`, `iter`, `len`, `is_empty`; edge flags in ascending edge order, with the mandatory-seam rule in its rustdoc); `SeamsError`. No charting yet | `openplush-mesh`, `thiserror` |
| `openplush-flatten` | `injectivity::verify(chart, faces)` takes `(FaceId, [DVec2; 3])` triangles and passes only if every one is strictly counter-clockwise by the exact `orient2d` predicate (det J > 0). `FlattenError`: `Flip` (every inverted or collinear face, in input order), `EmptyChart` (no faces), `Unjudgeable` (a face with a non-finite or extreme coordinate, the predicate's `GeomError` attached; it is returned at once and wins over a flip found earlier). No other flatten code yet | `openplush-geom`, `openplush-mesh`, `openplush-seams`, `thiserror` |
| `openplush-io` | `Format` (OBJ, glTF, GLB, STL, PLY); `IoError` (`Parse`, `NonFiniteInput`, `Mesh`); `obj::read(bytes)`, OBJ to `TriangleSoup`. The OBJ reader reads `v`, `vt` (`v` defaults to 0) and `f` in all four corner forms, with negative indices counting back from the line and positive ones checked against the whole file. Every `v` line becomes a soup vertex in file order, used or not, and only its first three numbers are read. A corner's provenance is its primitive and its 0-based position index. A primitive is a maximal run of `f` lines with no `o`, `g` or `usemtl` between them, numbered from 0, so one material each. The soup's `SourceMaterials` holds the `usemtl` names exactly as written (trailing blanks kept, a comment ends the name), each once in first-use order, including a name no face uses; a `\`-continued name keeps any blanks before the backslash and gains one space at the join; a primitive's material is the last `usemtl` before its faces, kept across `o` and `g`, or none if no `usemtl` came first. No MTL file is read, and `extra_uv_sets` is 0. A `v` line takes the primitive current where it appears. Corner UVs are present only if some face gives one. A leading byte-order mark is skipped, `#` comments are stripped and `\`-continued lines joined. Normals, smoothing, lines and points are skipped; free-form geometry (`cstype`, `curv`, `curv2`, `surf`) is refused, since skipping it would lose surface. Non-UTF-8 text (anywhere, comments included) and more than 2^32 − 1 vertices are refused as `Parse`; so is any statement that cannot be read, with a detail starting `line N:`: a non-number, a vertex with under three coordinates, a non-finite UV, a `usemtl` with no name, a face with under three corners, an index of 0 or out of range, and a polygon that crosses itself. `NonFiniteInput` lists every NaN or infinite vertex, used or not, in file order. Triangulation never moves or adds a vertex: a quad splits on its shorter diagonal unless that diagonal lies outside; a larger polygon is ear-clipped on the plane its Newell normal faces, with exact predicates, and a corner that coincides with an ear's corner does not block it, so a hole joined by a doubled bridge edge clips. A polygon with no split whose triangles all turn its way is refused, unless its corners are collinear: then it is split and validation reports the zero-area triangles. Ear-clipping is quadratic in the polygon's corner count, so an OBJ face of more than 1000 corners is `Parse` (`line N:`). `stl::read(bytes)`, STL to `TriangleSoup`: a file is binary when its length is exactly `84 + 50 * n` for the `n` its header declares, otherwise ASCII text starting with `solid` (after blanks and a byte-order mark). Each triangle gives three soup vertices in file order, joined by the weld; a corner's provenance is primitive 0 for binary and the solid's 0-based index for ASCII, with its vertex position; no UVs, and one material-less primitive per solid. Facet normals and attribute bytes are not read. `Parse` details for ASCII start `line N:`; a file that is neither form names its length and the length its header declares; `NonFiniteInput` names every NaN or infinite vertex; more than `u32` vertices is `Parse`. `ply::read(bytes)`, PLY to `TriangleSoup`, ASCII or binary little or big endian. The `vertex` element (before `face`, each at most once) gives the soup's vertices in file order from scalar `x`, `y`, `z` of any numeric type and, if it has both, a texture pair (`s`/`t`, `u`/`v`, `texture_s`/`texture_t`, `texture_u`/`texture_v`) that each corner copies from its vertex; the `face` element's `vertex_indices` (or `vertex_index`) list gives polygons, triangulated, of 3 to 1000 corners. List count and item types must be integers, and an ASCII integer must fit its declared type; an ASCII `float` is rounded to 32 bits as a binary one is. A corner's provenance is primitive 0 and its vertex position; other properties and elements are read past. `Parse` details start `line N:` or `byte N:` where the reader can say where; `NonFiniteInput` names every NaN or infinite vertex. | `openplush-geom`, `openplush-mesh`, `thiserror` |
| `openplush-pattern` | `PieceId`; `parity::check(chain, a, b)` passes two seam-side lengths (`Mm`) if they differ by at most `SeamParity::DEFAULT` for the longer side, else `PatternError::SeamParity { chain, a, b, tolerance }`. `Outline::new(points)` builds a closed, simple, counter-clockwise polygon in mm or refuses it (`OutlineTooShort`, `OutlineNotFinite`, `OutlineNotSimple { edge, other }` for a repeated point, crossing, touching, overlap or fold, `OutlineClockwise`, `OutlineUnjudgeable`); it never reverses or repairs. `PatternPiece::new(id, sewing_line, cut_line, cut_quantity, rotations_deg)` refuses `ZeroCutQuantity`, `TooManyCuts { cut_quantity }` (over 100), `NoRotations` and `NonFiniteRotation { index }`, and reads back through accessors. `Fabric::new(FabricSpec)` checks a fabric profile (`FabricId`, name, `FabricCategory` `Woven`/`Knit`/`Pile`/`Felt`, grain, cross and bias stretch in percent, nap, pile length, thickness, frays, default allowance, roll width) and refuses `BadStretch { fabric, direction, percent }` (negative or not finite; `StretchDirection` `Grain`/`Cross`/`Bias`), `ZeroRollWidth`, `ZeroAllowanceFrays` and `PileWithoutNap` (pile with a length but no nap); it never adjusts a value. Derived, never stored: `rotations_deg()` is `[0]` with a nap, else `[0, 90, 180, 270]` for felt, else `[0, 180]`; `asks_mirroring()` is true for pile, whose export asks print-mirrored or as-is every time. `scale::size(model_longest, target)` returns the `Scale` and a `SizeRange` (`Below`, `Within`, `Above`, against 75 mm to 1000 mm, both ends within) for a `SizeTarget`: `LongestDimension(Mm)`, judged on that length itself, or `Reference { model_length, finished }`, judged on the model's longest dimension once scaled. Out of range is a `SizeRange`, never an error; it refuses `BadModelLength { model_length }` (zero, negative or not finite) and `BadScale { source }` (a scale or finished length that is zero or not finite) | `openplush-geom`, `openplush-mesh` (`id_newtype!`), `openplush-seams`, `thiserror` |
| `openplush-layout` | `shelf::pack(pieces, opts)` lays every copy of every `PatternPiece` on shelves across a roll, tallest first (ties by `PieceId`), and returns one `Sheet` as wide as the roll and as long as the shelves need. Each piece uses its first allowed rotation, which must be a multiple of 90 degrees (the turn is exact, with no trigonometry). `LayoutOptions::new(roll_width, gap, mirrored)`; `Sheet` (`width_mm`, `length_mm`, `placements`) and `Placement` (`piece`, `copy`, `rotation_deg`, `offset`, `mirrored`: mirror about the y-axis, then rotate counter-clockwise, then move by `offset`). `pages::tile(sheet, paper)` covers a `Sheet` with the fewest portrait pages of `Paper::Letter` or `Paper::A4`: each prints inside a 10 mm margin and repeats 15 mm of its right and bottom neighbours, so pages join by overlapping, never by trimming. It returns a `PageTiling` (`paper`, `rows`, `columns`, `pages`, row by row from the sheet's top edge, its highest y since sheets are y-up, each row left to right) of `Page`s (`row`, `column`, and the sheet window `window_min` to `window_max` in mm, which may run past the sheet's edge, and `label()`, row letter then column number from 1, such as "B3"). `PageTiling::marks()` lists registration mark centres in sheet mm: two on each edge two pages share, centred across the 15 mm band at a quarter and three quarters along the edge, so each prints on both pages; edges between columns row by row, then edges between rows. `LayoutError`: `BadRollWidth`, `NoPieces`, `PieceTooWide`, `TooManyPages` (over 26 pages across or down), `UnsupportedRotation` | `openplush-geom`, `openplush-pattern`, `thiserror` |
| `openplush-testkit` | Dev-dependency only. `fixtures`: `load(Kind, name)` returns a fixture's bytes, `names(Kind)` lists every fixture of a kind sorted, and `FixtureError` covers a bad name, a missing file, an entry that is not a file and a read error. Kinds: `Mesh` (`fixtures/meshes/*.obj`), `Defect` (`fixtures/defects/*.obj`), `Seams` (`fixtures/seams/*.json`). `oracles`: checks that recompute a property of a flattened `Chart` (plain `xyz`, `uv` and face arrays) from raw coordinates, independent of the code under test: `injective` (every flat face strictly counter-clockwise, exact predicate), `developable` (both signed singular values within a tolerance of 1, so a mirrored face fails) and `area_conserved` (signed flat area within a relative tolerance of 3D area); and, on plain values, `outline_simple` (a closed outline with no crossing, touching, zero-length or doubled-back edge, wound counter-clockwise, all by exact predicates; an outline the predicates cannot decide fails) and `seam_parity` (max(1.0 mm, 0.5% of the longer side), restated rather than taken from `SeamParity`). Each reports an `OracleFailure`, which names the face, edge or lengths involved where one applies; a chart with no faces fails as `Empty`, and a NaN, infinite or negative tolerance as `BadTolerance` | `openplush-geom`, `openplush-mesh`, `thiserror` |
