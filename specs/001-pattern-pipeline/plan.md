## Pipeline Architecture

```
bytes ─▶ import ─▶ TriangleSoup ─▶ validate ─▶ ValidationReport
                                     │
                         RepairPlan ─▶ repair ─▶ ManifoldMesh + RepairReport
                                                    │
                              SeamSet (user) ─▶ chart ─▶ Vec<ChartMesh> + SewingMap
                                                    │      (cut-graph completion proposals)
                                   FlattenOptions ─▶ flatten ─▶ Parameterization + Metrics
                                                    │
                     Fabric + DirectionField ─▶ orient ─▶ grain angle per chart
                                                    │
                       Scale + PatternOptions ─▶ pattern ─▶ Vec<PatternPiece>
                                                    │
                                 LayoutOptions ─▶ layout ─▶ Vec<Sheet>
                                                    │
                                                 export ─▶ SVG / PDF bytes
```

- **Functional core**: each stage is a pure function of its inputs. `openplush-pipeline` memoizes by content hash, so a seam edit re-runs `chart` → `flatten` only for charts whose face set or boundary changed (FR-014).
- **Scale is late**: flattening is scale-equivariant; resizing re-runs only `pattern` onward.
- **Sessions for long stages**: `FlattenSession::step() -> Progress` lets the worker yield between iterations for progress and cancellation (single-threaded WASM).

### Warnings vs. errors (D-016, D-017)

Two distinct channels, never conflated:

| | Error | Warning |
|---|---|---|
| Means | A declared invariant is violated (Constitution III) | The geometry is valid but the result may sew badly |
| Examples | Chart is not a disk; det J ≤ 0; seam parity outside max(1.0 mm, 0.5%); allowance offset self-intersects unresolvably | Unsupported concavity (FR-025); low nap coherence (FR-052); piece smaller than 3× pile length (FR-055); stretch mismatch across a seam (FR-058) |
| Type | `Err(EngineError)` — the stage does not produce output | `Ok(output)` carrying a `WarningSet` |
| Effect on export | **Blocks** | **Never blocks** — acknowledged once, then unresolved entries print on the pattern's first page (FR-064) |

- `WarningSet` accumulates across stages and travels with the pipeline output. Each `Warning` carries a stable code, a located target (face/edge/piece ID), a plain-language explanation, and a `Remedy` (FR-065).
- `Remedy` is either `Actionable { proposal }` — an engine-computed change the UI offers preview-then-accept (extra seam FR-013, dart FR-022, piece split FR-052) — or `Advisory { what_to_change }`, naming a material or sizing choice the engine will not perform (FR-055, FR-058). A `Warning` with neither is a compile-time impossibility, which is how FR-065 is enforced rather than reviewed.
- Warnings are deterministic and ordered like everything else (Constitution V): sorted by code then by target ID, so the first-page summary is byte-stable.

### Worker boundary
- Mesh and intermediate state stay resident in the worker; the UI holds opaque handles.
- Control messages: small JSON (typed from `contracts/worker-protocol.md`; TS types generated from Rust).
- Geometry for rendering: transferable `Float32Array` / `Uint32Array` buffers (zero-copy transfer).
- Errors cross as typed `EngineError` codes with locations (face/edge IDs) the UI can highlight.

### Trade-offs accepted
- Smaller engine contributor pool (Rust) in exchange for zero-install distribution and one engine everywhere.
- No free seam-marking UI from Blender; we build seam drawing in Three.js.
- Single-threaded WASM in MVP; performance budget met by remeshed flattening proxy.
- No Spec Kit agent-context extension: `AGENTS.md` doesn't auto-list the current plan path; `.specify/feature.json` covers that.
