# Crates

What each engine crate contains **today**, and what it actually depends on. Which crate *should* own a new piece of code is a rule, kept in [`crates/AGENTS.md`](../../crates/AGENTS.md#where-code-goes); the allowed dependency graph is in the [plan](../../specs/001-pattern-pipeline/plan.md#crate-dependency-dag-enforced) and enforced by `scripts/check-boundary.sh`. Signatures and item docs: `cargo doc --workspace --no-deps --open`.

## Built

| Crate | Public items | Depends on |
|---|---|---|
| `openplush-geom` | `DVec2`, `DVec3`; exact predicates `orient2d`, `orient3d`, `incircle` returning `Sign`; `epsilon` (`ModelTolerances`, `SeamParity`, and the constants behind them); `units` (`Mm`, `Scale`); `GeomError` | `robust`, `thiserror` |
| `openplush-mesh` | `TriangleSoup` and `SourceCorner`; `SourceMaterials` (`names`, `by_primitive`, `material(primitive)`) and `MaterialIndex`, which a soup carries with `extra_uv_sets` (UV sets the file has beyond the one read): `TriangleSoup::new` gives an empty table, `with_materials(materials, extra_uv_sets)` sets them, and repair moves both unchanged onto the mesh; the half-edge `ManifoldMesh` (read-only accessors including `materials` and `extra_uv_sets`, `outgoing` returning `Outgoing`, `boundary_loops`, `debug_validate`; no public constructor); IDs `VertexId`, `EdgeId`, `HalfEdgeId`, `FaceId`, `ComponentId`, `MeshElement`, and `id_newtype!`, which defines a `u32` ID with `new`, `index` and the shared derives; `MeshError` with `CornerArray`, `Counted` and `MaterialFault`, where `InvalidMaterial` names the lowest primitive that a triangle uses but the table lacks (`Missing`), or whose material is not below the name count (`OutOfRange`); `validate(&TriangleSoup) -> ValidationReport`, which never fails and changes nothing. It welds used vertices within the weld distance (transitively, comparing only vertices in neighbouring weld-distance cells) and leaves out repeated-index faces and later copies wound the same way, keeping both layers of a double-sided sheet, then judges topology on what remains, as repair will see it; a vertex there is named by its weld group's smallest ID. The report lists, each sorted: `unwelded` groups; `zero_area` faces (area at or below the area tolerance, from the soup's own positions); `repeated_index` faces; `duplicates` (`Duplicate`: the copy, the first face it repeats wound its way or, for `DuplicateOrientation::Opposite`, the other way, and `Same` or `Opposite`); `non_manifold_edges` (`NonManifoldEdge`: ends and every face); `non_manifold_vertices` (faces split into more than one fan joined through shared edges); `winding_conflicts` (two-face edges both faces walk the same way); `non_orientable` (two-face edges where the flips a breadth-first walk assigns contradict); `inside_out` (shells, faces joined across two-face edges, that are closed and have non-positive signed volume, so an inside-out shell touching the rest only at a vertex or a non-manifold edge is still caught; a shell made only of a double-sided sheet's layers is closed and flat but not listed, since repair leaves its winding as it is); `boundary_loops` (one-face edges chained in their faces' direction, split wherever a vertex repeats, each from its smallest vertex); and `components` (vertex-connected, by faces; more than one is a defect). A soup with no triangles or an extent tolerances refuse is `Unmeasurable` (`NoTriangles`, `Extent { diagonal }`) with nothing else judged. `self_intersections` lists face pairs sharing no edge that cross along a segment longer than the weld distance, so a fold between faces sharing a vertex counts; faces that only touch (at a corner or edge-on), lie within the weld distance of one plane, or have no area are not listed, so shells overlapping only through coplanar faces go unreported. Candidates come from a bounding-box tree; the test is in floating point against the weld distance, since the report only warns. A vertex of valence k costs about k² pair tests | `openplush-geom`, `thiserror` |
| `openplush-seams` | `Proposal` (built only by `Proposal::new`), `ProposalId`, `ProposalKind`, `SeamReason`; `SeamKind`, `ChartFailure`; IDs `ChartId`, `SeamChainId`; `SeamSet` (`new`, `get`, `insert`, `remove`, `iter`, `len`, `is_empty`: edge flags in ascending edge order; `insert` and `remove` return the previous kind, and a `Mandatory` seam can be neither removed nor given another kind, else `MandatorySeam`); `SeamsError`. No charting yet | `openplush-mesh`, `thiserror` |
| `openplush-io` | `Format` (OBJ, glTF, GLB, STL, PLY); `IoError` (`Parse`, `NonFiniteInput`, `Mesh`); `obj::read(bytes)`, OBJ to `TriangleSoup`. The OBJ reader reads `v`, `vt` (`v` defaults to 0) and `f` in all four corner forms, with negative indices counting back from the line and positive ones checked against the whole file. Every `v` line becomes a soup vertex in file order, used or not, and only its first three numbers are read. A corner's provenance is its primitive and its 0-based position index. A primitive is a maximal run of `f` lines with no `o`, `g` or `usemtl` between them, numbered from 0, so one material each. The soup's `SourceMaterials` holds the `usemtl` names exactly as written (trailing blanks kept, a comment ends the name), each once in first-use order, including a name no face uses; a `\`-continued name keeps any blanks before the backslash and gains one space at the join; a primitive's material is the last `usemtl` before its faces, kept across `o` and `g`, or none if no `usemtl` came first. No MTL file is read, and `extra_uv_sets` is 0. A `v` line takes the primitive current where it appears. Corner UVs are present only if some face gives one. A leading byte-order mark is skipped, `#` comments are stripped and `\`-continued lines joined. Normals, smoothing, lines and points are skipped; free-form geometry (`cstype`, `curv`, `curv2`, `surf`) is refused, since skipping it would lose surface. Non-UTF-8 text (anywhere, comments included) and more than 2^32 − 1 vertices are refused as `Parse`; so is any statement that cannot be read, with a detail starting `line N:`: a non-number, a vertex with under three coordinates, a non-finite UV, a `usemtl` with no name, a face with under three corners, an index of 0 or out of range, and a polygon that crosses itself. `NonFiniteInput` lists every NaN or infinite vertex, used or not, in file order. Triangulation never moves or adds a vertex: a quad splits on its shorter diagonal unless that diagonal lies outside; a larger polygon is ear-clipped on the plane its Newell normal faces, with exact predicates, and a corner that coincides with an ear's corner does not block it, so a hole joined by a doubled bridge edge clips. A polygon with no split whose triangles all turn its way is refused, unless its corners are collinear: then it is split and validation reports the zero-area triangles. Ear-clipping is quadratic in the polygon's corner count | `openplush-geom`, `openplush-mesh`, `thiserror` |
| `openplush-pattern` | `PieceId`. No pattern code yet | `openplush-mesh` (for `id_newtype!`) |
| `openplush-testkit` | Dev-dependency only. `fixtures`: `load(Kind, name)` returns a fixture's bytes, `names(Kind)` lists every fixture of a kind sorted, and `FixtureError` covers a bad name, a missing file, an entry that is not a file and a read error. Kinds: `Mesh` (`fixtures/meshes/*.obj`), `Defect` (`fixtures/defects/*.obj`), `Seams` (`fixtures/seams/*.json`). `oracles`: checks that recompute a property of a flattened `Chart` (plain `xyz`, `uv` and face arrays) from raw coordinates, independent of the code under test: `injective` (every flat face strictly counter-clockwise, exact predicate), `developable` (both signed singular values within a tolerance of 1, so a mirrored face fails) and `area_conserved` (signed flat area within a relative tolerance of 3D area); and, on plain values, `outline_simple` (a closed outline with no crossing, touching, zero-length or doubled-back edge, wound counter-clockwise, all by exact predicates; an outline the predicates cannot decide fails) and `seam_parity` (max(1.0 mm, 0.5% of the longer side), restated rather than taken from `SeamParity`). Each reports an `OracleFailure`, which names the face, edge or lengths involved where one applies; a chart with no faces fails as `Empty`, and a NaN, infinite or negative tolerance as `BadTolerance` | `openplush-geom`, `openplush-mesh`, `thiserror` |
| `openplush-pipeline` | The public API: `EngineError`, the warning types, `Staged`/`StageResult`, and re-exports. See [engine-api.md](engine-api.md) | `openplush-io`, `-mesh`, `-pattern`, `-seams`, `thiserror` |
