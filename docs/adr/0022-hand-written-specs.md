# Specs are written by hand from templates in specs/, and the constitution lives at the root

## Context and problem statement

Since 2026-10-13 ([001 D-011](https://github.com/openplush/openplush/blob/main/specs/001-pattern-pipeline/plan.md#decision-ledger)) specs, plans and task lists were generated by an external tool: a pinned dev build installed under a hidden root folder, 15 generated Claude Code skills, a git extension with hooks, shell scripts and a local active-feature pointer. The agent rules forbade hand-editing any of it. In practice every feature's files are edited by hand after generation. The merge gate reads the project's own conventions (task tokens, the Decision Ledger, tiers), not the tool's. The tool's branch naming had to be renamed before every push, and its scripts needed a Windows workaround. Should the project keep a generator it does not use, whose files no one may edit?

## Decision drivers

* One home per rule (AGENTS.md, DRY): the generated skills restated the workflow the agent rules already state, and could disagree with it.
* YAGNI: no dependency or tooling without a task that uses it now.
* Contributor burden: a maintainer writing a spec should need a template, not a CLI install.
* The binding principles must stay maintainer-merged wherever they live.

## Considered options

* Keep the generator.
* Drop it: specs are written by hand from templates in `specs/templates/`, and the constitution moves to `CONSTITUTION.md` at the root.

## Decision outcome

Chosen option: **drop it**. The spec flow (specify, clarify, plan, tasks, implement), task IDs, readiness tokens and the Decision Ledger stay the project's own. Only the tool goes [solid]. 001 D-011 is superseded. `CONSTITUTION.md` keeps its content and version; the move is not an amendment.

### Consequences

* Good, because every file in the spec flow can be edited by hand, and its rules live once, in `AGENTS.md` and the skills the project writes.
* Good, because a feature branch is named correctly from the start, with no rename step.
* Bad, because no tool checks a new spec against its template; `spec-reviewer` and the maintainer's review are the only checks.

### Confirmation

`.github/CODEOWNERS` assigns `CONSTITUTION.md` to the maintainer, and no tracked file names the generator or its folder.
